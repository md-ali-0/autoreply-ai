# v1.52.1 — Device Verification Report

Device: **vivo V2237 / 10ED3Y015E00028**, Android (targetSdk 35)
Build under test: `verifyOnly` — minified with R8 (`minifyEnabled` + `shrinkResources`),
the same code path as `release`, but `isDebuggable = true` so results could be read back.
Result: **all checks pass**, and **two real defects were found and fixed** (`v1.52.1`).

---

## Why a special harness was needed

The shipped release sets `isDebuggable = false`, which is one of the P1 fixes — and it means
`adb shell run-as` is refused, so app data cannot be read over adb. That is correct and was
confirmed:

```
$ adb shell run-as com.claw.autoreplyai id
run-as: package not debuggable: com.claw.autoreplyai
```

So a read-back channel had to exist *before* shipping. `adb backup` was tried first and is a
dead end: its confirmation dialog sits behind the keyguard and `uiautomator dump` only sees
the notification shade.

Two temporary variants were added (`app/src/verify`, `app/src/verifyOnly`), both with
`applicationIdSuffix = ".verify"` so they install alongside the real app without touching its
data. A `VerifyProbe` object ran at boot and wrote findings into its own prefs bucket.

**Running the same probe on minified and unminified builds is the point**: if a check passes
on one and fails on the other, R8 is the cause.

## Defect 1 (real) — phone normalisation kept the `+`

`normalizePhone` preserved a leading `+`, so one person could produce three keys:

| form | old identity |
|---|---|
| `+880 1321-329293` | `p:+8801321329293` |
| `8801321329293` | `p:8801321329293` |
| `01321329293` | `p:01321329293` |

Not hypothetical: this device's own prefs contain both `last_+880 1321-329293` and
`last_+18188690326`, and within one app a notification can show the international form while
the sender record for the same thread carries the bare local one. Each spelling got its own
memory bucket and its own cooldown — the exact collision class `ConversationKey` exists to
remove.

**Fixed**: canonicalise, don't just tidy. Digits only, no `+`, bare local numbers folded
through the configured country code; explicit `+` and already-international numbers left
alone; foreign numbers preserved.

```
phone-all-forms-same: true
   form[0] '+880 1321-329293' -> p:8801321329293
   form[1] '8801321329293'    -> p:8801321329293
   form[2] '+8801321329293'   -> p:8801321329293
   form[3] '01321329293'      -> p:8801321329293
   form[4] '01321 329293'     -> p:8801321329293
no-double-prefix: p:8801321329293
foreign-preserved: p:18188690326
```

## Defect 2 (latent) — `restorePending` trusted the persisted `addr`

`addr` was the **map key** while `key` (from `convId`/`convPkg`) was the **conversation
identity**. When they disagree the entry is keyed where its own conversation can never find
it — cooldown and memory lookups use `key`, so the reply sits unreachable in the queue. They
can disagree because a v1.51 entry has no `addr` at all, and a v1.52 entry written before the
country code was set resolved a local number differently.

**Fixed**: derive the address from the recomputed key; ignore the stored one. Proved with a
deliberately wrong `addr` in the payload.

## Harness gotchas, for next time

1. **`isDebuggable = false` blocks `run-as`.** Decide the read-back channel before shipping,
   not after.
2. **`Application.onCreate` runs before the accessibility service binds.** A queue probe
   there always sees a null `instance`; trigger it from `onServiceConnected`.
3. **Never `CountDownLatch.await()` on the main thread from `onCreate`** to wait on an
   `h.post{}` — the post queues behind the blocked thread and can never run. Symptom: the
   probe prints its header and nothing else.
4. **`apply()` is asynchronous.** Reading a prefs file straight after `restorePending` races
   the flush and reports the pre-*restore* content. Assert on the in-memory queue.
5. **A probe must wipe its own state first.** Otherwise last run's entries make the correct
   refusal-to-double-queue look like a failure.
6. **`settings put secure enabled_accessibility_services`** needs the target package's own
   component, and a disable→enable cycle to force a rebind after install. Installing kills
   the service; it rebinds lazily.
7. **`adb push` is unaffected here but `adb backup` needs an on-device tap** — impossible
   behind the keyguard.

## Still open (needs a decision, not more code)

- **Room migration** — recommend **against**. The access pattern is "many small independent
  keyed blobs, replaced whole"; there is no query side, so Room's value does not apply. The
  v1.52 defect was *identity*, not the storage engine — keying by `String.hashCode()` is
  broken in SQLite exactly as badly as in SharedPreferences.
- **Encrypted cloud backup** — needs a key-management decision. A device-derived key cannot
  survive a factory reset, so a real backup needs either a user passphrase or a server-held
  key; the latter changes the privacy posture materially.
- **P2 batch** — provider stable ID, custom Base URL validation, provider health,
  permission review, `KeepAliveService` reassessment.

See `docs/v1.52-deferred-proposal.md`.
